# HFPager-совместимый пейджер для Windows (экспериментальный)

Файлы: `hfpager_app.py` (окно программы), `hfpager_rx.py` (приёмник с АПЧ), `hfpager_modem.py`
(кодек протокола и передатчик), `HFPAGER_PROTOCOL.md` (описание формата).

## Запуск
1. Установите Python 3.10+ для Windows (с галочкой «Add to PATH» и компонентом tcl/tk).
2. Дважды щёлкните `run_hfpager.bat` (он поставит `numpy` и `sounddevice` и запустит программу)
   или выполните `py -m pip install -r requirements.txt` и `py hfpager_app.py`.
3. Отдельный `HFPagerApp.exe`: запустите `build_exe.bat` на Windows (нужен интернет для установки PyInstaller).

## Как пользоваться
* **Мой ID** – ваш собственный номер станции (0…65535); он попадает в поле «отправитель».
* **Вход / Выход** – звуковые устройства: вход принимает звук от приёмника, выход подаётся на
  микрофонный/линейный вход трансивера (SSB). Для лучшей работы – внешний USB-интерфейс,
  отключите «улучшения звука» Windows, частота дискретизации 48000 Гц.
* **Кому (ID)** + поле текста + **Отправить** (или Enter). Текст до 252 байт (кодировка Windows-1251).
* **Скорость** 5.86 или 23.44 Бод для передачи; приём распознаёт обе автоматически.
* **Тон 0, Гц** – частота нулевого тона (группа из 18 тонов занимает ~200 Гц на 5.86 Бод и ~400 Гц
  на 23.44 Бод). **Уровень TX** держите таким, чтобы не было ALC-ограничения. **Задержка PTT/VOX** –
  пауза перед сигналом, чтобы трансивер успел перейти на передачу (VOX). Управления PTT по
  COM-порту в этой версии нет.
* **Порог приёма, дБ** – превышение «остроты» спектра над шумом для обнаружения сигнала (по умолчанию 4).
* В окне обмена показываются все принятые кадры: зелёным – адресованные вам, фиолетовым – маяки,
  серым – повторы.

## АПЧ (автоподстройка частоты)
Приёмник сам находит группу тонов в звуковом спектре (настройка по частоте не нужна), по
преамбуле определяет положение нулевого тона и далее отслеживает по каждому символу уход частоты
(контур первого порядка); при неудаче пробует другие коэффициенты слежения, сдвиги фазы символов
и поправку на расхождение частот дискретизации. В тестах декодируются кадры при расстройке
по частоте, дрейфе, скачках на полтона и расхождении тактов звуковых карт до ±300 ppm.
Флажок «АПЧ» можно отключить (останется приём по разностям тонов).

## Проверено / не проверено
* Проверено: кодек на 47 записях 5.86 Бод и 5 записях 23.44 Бод; поток из реальных записей;
  синтетика с шумом (декодирование до ≈ −6 дБ ОСШ в полосе 2.7 кГц на 5.86 Бод) и без ложных
  срабатываний на шуме; передача→приём «через петлю» с имитацией звуковой карты.
* **Не проверено:** интерфейс запускался только с имитацией tkinter (без настоящего экрана Windows),
  работа с реальной звуковой картой и трансивером, совместимость в эфире с оригинальным приложением.
* Подтверждения доставки: приём ACK-кадров и отметка «доставлено» работают; автоподтверждение
  (флажок «Автоподтверждение (экспер.)») построено по одной записи ответа и совместимость с оригиналом в эфире
  не проверена; NAK не реализован.
* Не реализовано: скорость 1.46 Бод, GPS,
  CW-позывной маяка, управление PTT.

Передача в эфир на КВ требует лицензии радиолюбителя.

## Интерфейс (обновление)
* Окно сообщений в стиле старых мониторов: чёрный фон; принятые – зелёные, отправленные – красные, служебные/прочие – жёлтые; шрифт крупнее (12 pt, на Mac 13 pt).
* «Монитор приёма»: лампы **RX** (зелёная – идёт приём, жёлтая – декодирование) и **TX** (красная – передача), шкала уровня входа в дБ с предупреждением о перегрузке и водопад спектра 300…3000 Гц.
